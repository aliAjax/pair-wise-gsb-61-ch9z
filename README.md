# 汽车型式认证证据包审阅与补件平台

用于按车型、配置、法规项目和维护版本组织测试报告、部件清单、软件版本及豁免材料的本地认证工作台。

## 技术栈

- Nuxt 3 + TypeScript
- Nuxt UI
- Pinia
- Nuxt Router
- ofetch
- TanStack Query for Vue

## 主要工作区

- `/`：认证项目列表、关键词/状态/机构/风险筛选和项目统计
- `/projects/new`：建立车型、配置、维护版本和软件版本基线
- `/projects/[id]`：证据审阅、法规覆盖、状态流转、版本差异、批量补件和审计
- `/batches`：离线复核批次（检出、导出/导入离线包、回网合并、两版取版、写入失败恢复）
- `/regulations`：按法规分类查看项目证据覆盖
- `/supplements`：跨项目批量补件
- `/reminders`：证书和证据到期提醒
- `/audit`：跨项目审批时间线与提交包导出

## 离线复核批次（续作合并）

审阅员在 `/batches` 把项目按当前快照**检出**为复核批次，导出离线包断网作业，回网后导入并提交：

- **三方合并**：检出基线 `base` × 回网时在线现状 `online` × 离线工作集 `offline`。状态、基线、证据、审计按字段/证据版本合并；仅一边改动直接采纳，新增证据并存不覆盖。
- **同一证据两边改过**：保留在线/离线两版（同一 `logicalId`、同一冲突组），置待复核，批次状态为"两版待复核"，在批次页逐组取版后归一。
- **软件基线联动**：软件版本一改，基于旧基线的证据立即 `staleAt` 失效并转待补件，受影响配置的法规覆盖、完整度与补件队列同步重算。
- **冻结只读**：`approved` 项目所有在线写入被拦截；回网时已冻结的离线包整包只读作废（`voided`），不覆盖任何在线数据。
- **写入失败恢复**：提交先写包含提交前/后完整批次快照的预写日志（WAL），失败时列表、详情、提交包仍读提交前同一份数据；恢复后从完整批次重新合并幂等重试，报告记录尝试次数。
- **单一事实源**：列表、详情、提交包都只读取同一份有效批次/项目状态；存在未取版两版证据时提交包阻断导出。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18461`。

## 构建、检查与场景验证

```bash
npm run typecheck
npm run build
node scripts/run-tests.cjs   # 49 项端到端断言：三方合并/双版本/失效联动/冻结/WAL 恢复
```

项目没有后端服务，使用结构化模拟数据，并通过 Pinia 和浏览器 `localStorage` 持久化车型项目、证据状态、版本和审计记录。ofetch 由本地模拟 fetch 适配器承载，TanStack Query 负责项目索引查询和筛选缓存。
